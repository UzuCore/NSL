# NSL outage recovery, disk-full simulation and native Windows GUI QA

Date: 2026-11-20 (KST). Windows local repository `D:\NSW.dev\NSL`; preceding source commit `3f91947`.

## Safety and scope

- All torrent transfers used generated bytes, ephemeral loopback `127.0.0.1` peer/tracker sockets and test-only `%TEMP%` directories. DHT, local peer discovery, public trackers and user download directories were not used.
- The disk-space test uses a bounded in-memory `Write` implementation returning `std::io::ErrorKind::StorageFull`; it **does not** fill a real disk or change any user's storage quota.
- GUI verification launches a fresh **copy** of the local release EXE in a unique temporary portable folder. Native window operations target only that test process without sending global mouse/keyboard events or activating other apps. The copy and its private database are removed afterward.
- Original `E:\NSW` ROMs, `library.db`, `config.json`, `prod.keys`, user downloads, other app processes, and published GitHub r22 artifacts are not modified. **GitHub Actions were not dispatched.**

## Real loopback seeder outage and recovery

New opt-in test: `torrent::localhost_tests::larger_transfer_survives_local_seeder_outage_and_restores_exact_bytes`.

- Generates **16,777,216 bytes (16 MiB)** and a local `.torrent` with 32 KiB pieces.
- Local seeder upload rate is limited to **768 KiB/s**; the client is a real NSL `TorrentEngine` with a persistent session and a real, ephemeral HTTP tracker.
- After receiving approximately **1 MiB**, `librqbit::Session::pause` interrupts the **test seeder only**. The client remains on the download list without marking the incomplete job as either successfully finished or fatally failed.
- After approximately 3 seconds of unavailable peer service, `Session::unpause` restarts the seeder. The client resumes automatically, finishes all data, and every output byte compares equal to the generated source.
- Isolated test measured **~32 seconds** including the interruption. Repeated together with the other two localhost E2E tests: **3 passed, 0 failed, ~50.40 s**.

The earlier two tests were also rerun after replacing duplicated single-file seeder setup with the common `local_file_seeder` helper. They independently verify: pause/resume, session restart and restored progress, deletion that preserves sibling/user files, nested torrent tree preview, and downloading only selected files. This is **local peer interruption**, not a test of an external WAN outage or a public tracker.

## Simulated disk-full error on native NCZ restoration

`src/ncz.rs` now funnels all restored-byte writes through a small `write_output` helper. When `write_all` reports `ErrorKind::StorageFull`, NSL preserves the OS error chain and gives the actionable Korean context **"NCZ 복원 파일을 저장할 디스크 공간이 부족합니다"**. Other write errors receive the separate **"NCZ 복원 파일 쓰기 실패"** context. The decoder always propagates failures and cannot claim a completed output after a partial write.

New default test `ncz::tests::simulated_disk_full_aborts_solid_and_block_restoration_without_overwriting_input` uses both **solid NCZ** and **NCZBLOCK** with deterministic synthetic encrypted sections. For each encoding, the test forces failure with three memory limits (0 bytes, after the first 16 KiB NCA header plus 32 KiB, and one byte before the full restored NCA length): **six failure cases passed**. It verifies the exact bytes written before failure, unchanged source contents and the Korean error. The block case includes valid plain trailing NCA data; the solid case intentionally does not, as the solid layout does not declare such data.

NSL's existing high-level conversion path still uses an atomic temporary output and cleans an empty workspace on failure, as independently covered by the previous `decompress::tests::failed_nsz_rebuild_removes_empty_workspace_and_preserves_source`. An actual filesystem full event, physical drive disconnect and write-protection failure were **not** inflicted on the user's machine.

## Real Windows native window operation (isolated)

New reproducible script: `scripts/qa-native-gui-window.ps1`.

1. Copies `target\release\nsl.exe` to a fresh `%TEMP%\NSL_GUI_NATIVE_*` directory and starts it as a separate process.
2. Verifies the application's real native Win32 main window and the build commit in its title, plus a private `library.db` in the temporary portable folder.
3. Changes the actual Win32 window's size, without activating it, to **980×720, 1280×800 and 1456×900**; each passes geometric readback, a responsiveness ping (`WM_NULL`), process-alive and not-hung checks.
4. Closes **only** the newly created GUI process and confirms its temporary directory is removed. No production NSL process is stopped or modified.

Initial native window smoke passed with the preceding local release `NSL 3f91947`; repeat the script with `-ExpectedCommit` **after the new source commit and local release rebuild**. Other egui tests in the default suite drive headless pointer/keyboard actions for store, downloads, selection dialogs, tab switching, splitter drag, Escape, filtering and scrolling. This Win32 smoke proves real window creation, resizing, and event-loop responsiveness; it **does not claim visual screenshot inspection or complete live-desktop mouse/keyboard workflow verification**.

## Regression summary and rerun

```powershell
cd D:\NSW.dev\NSL
cargo test --locked --all-targets -- --test-threads 4
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --bin nsl torrent::localhost_tests:: -- --ignored --nocapture --test-threads 1
cargo test --locked --bin nsl simulated_disk_full_aborts_solid_and_block_restoration_without_overwriting_input -- --test-threads 1
cargo build --locked --release
.\scripts\qa-native-gui-window.ps1 -ExpectedCommit (git rev-parse --short HEAD)
```

Full default Rust suite: **174 passed, 0 failed, 17 ignored**; Clippy `-D warnings`: **PASS**. The three localhost torrent tests were run deliberately outside the default suite and all passed. The other ignored environment-dependent cases were **not all executed**. The final published executable for the user must be rebuilt in the local `target\release` directory **after** committing the source so the `NSL_BUILD_COMMIT` embedded by `build.rs` corresponds to the actual source revision. No official r22 release update is implied.

## Remaining risks

Manual GUI interactions on the user's real desktop, long public-peer transfers and unpredictable WAN outages, physical disk-full/device removal, independently reproducible release-profile throughput/peak RAM, and actual game launch/emulator compatibility remain separate from these isolated checks. The single historical XCZ with 411 bytes missing from its declared secure partition remains correctly rejected rather than being treated as valid padding.
