# NSL Rust v2.0.0 — reliability and performance hardening

Date: 2026-11-18. Scope: local `D:\NSW.dev\NSL` working tree. User game files and the existing `library.db`, `config.json`, and `prod.keys` were not modified during this work. The Windows installer, error handling, and database rollback tests use isolated temporary directories.

## Data protection

- **Update installation:** `package-rust.ps1` no longer packages a new `library.db`, preventing the older `xcopy` installer from replacing an existing library. SHA-256 checksums of the three executable payloads are embedded in the release manifest; the updater validates their integrity and restricts the source to HTTPS releases of `UzuCore/NSL`. `scripts/extract-update.ps1` checks for Zip Slip and caps expanded archive size. `scripts/apply-update.ps1` stages and atomically replaces ONLY the three executables and manifest, attempts rollback on failure, and never copies the database, config, local title DB, icons, screenshots, keys or downloads. This does **not** replace a publisher signature; HTTPS/manifest hash checks cannot defeat a malicious publisher account.
- **Config:** atomic replacement with `.json.bak` recovery. Corrupt JSON no longer resets settings silently.
- **Title DB:** all SQLite title updates use one transaction, rollback on an injection-triggered failure; online metadata is bounded, validated and atomically replaced.
- **Scanner:** traversal errors suppress destructive pruning for the affected root, increment scan errors, and preserve prior records. Incremental scan re-analyzes when the scan schema differs. Headless mode does not change GUI media download preferences. Files shorter than 16 bytes are reported as corrupt rather than indexed as successful.
- **Image and conversion data:** images use a 32 MiB transfer cap and a 24-megapixel predecode limit, and cache files are replaced atomically. Old NSZ/XCZ conversion workspaces are not silently removed while other processes may still be using them.

## Downloads and UI

- **Torrents:** child download directories are correctly restored after restart, and each torrent has its own safe relative `BASE-HASH` subdirectory. Real download results are different events from pause/resume/remove acknowledgements; errors are preserved. A pending magnet can be cancelled. Finished items can be removed from persisted session metadata without deleting downloaded files. Session-data cleanup is deferred to next app launch, before rqbit initialization.
- **Rendering:** `Arc` shares filtered game rows across UI frames; the library list is virtualized (the grid already was), exception changes invalidate caches, store search uses cached indices for the full catalog instead of a 2,000-row cutoff, and store cover textures have a 128-item LRU bound. Catalog cover IDs are validated before writing paths.
- **Paths:** portable binaries no longer adopt an unrelated parent folder's database. Renamed mixed-content NSPs retain their base title ID, supporting later fallback analysis.

## Still requiring separate environment / device verification

- Real public-domain or user-authorized BitTorrent peer-to-peer transfer, pause/resume/cancel, exit and re-launch E2E scenarios.
- Some lower-priority compatibility issues (e.g. Windows-specific launcher argument quoting, large-scale manual UI interaction, and splitting the monolithic `main.rs`) remain candidates for a later focused pass.
- XCI/XCZ real corpus validation (current local corpus includes only NSP and NSZ).
- Manual multi-monitor Windows GUI click/keyboard, scroll, startup and shutdown verification; memory/CPU profiles with a very large library.
- Release signing, dependency vulnerability auditing, and publishing to GitHub are separate release work and not claimed here.

The build and distribution package should be produced from these sources, not from an older `dist-rust\nsl.exe`.
