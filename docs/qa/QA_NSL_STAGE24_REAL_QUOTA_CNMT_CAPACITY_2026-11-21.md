### Local quota preflight (no disk filling)

- The Missing Updates / Missing DLC batch queue obtains available bytes from `fs2::available_space` on the **actual downloads drive** before accepting new groups. It reserves **remaining bytes of active torrents**, outstanding matching jobs after restart and the **selected unique file sizes** across all groups already admitted.
- Each admitted group reserves **64 MiB of additional free headroom** for filesystem bookkeeping. Size arithmetic uses checked operations and rejects overflow or zero-sized downloads. A missing/unreadable free-space reading causes a Korean error and **does not enqueue** any transfer.
- The real queue uses these preflight readings; deterministic isolated tests can pass an explicit budget to the same queue path, avoiding risky host-volume consumption.
- `stage24_batch_capacity_accounts_for_prior_jobs_and_overflow`: **PASS** for cumulative queue reservation, a 64 MiB capacity boundary, zero size, checked overflow and exact-fit behavior.
- `stage24_insufficient_batch_space_does_not_enqueue_or_change_original`: **PASS**. A private 32 MiB update candidate under a simulated **10 MiB available** capacity was rejected without creating a batch download folder, registering a torrent job or altering the private original-file sentinel.
- This is **advisory admission control**. The disk can become full later due to other programs, network filesystems may misreport free space, and reservations are not enforced NTFS quotas; the real live write-error recovery above remains essential.

## Strict Title ID / version candidate matching before downloads

- `src/update_batch.rs` now extracts **exactly one 16-digit hex Title ID** and at most **one valid numeric `[vNNN]` version token** from each positive-size NSP/NSZ torrent file candidate. Multiple IDs, conflicting versions, nonnumeric/negative/overflow versions, empty files, unsupported extensions and traversal paths are excluded.
- Update candidates require a real 16-hex **base game Title ID**, aligned on the base-game mask, and a positive patch version **strictly newer than installed and at least the title DB's required version**.
- DLC candidates require an exact 16-hex DLC Title ID. Valid **DLC version 0** remains supported when `[v0]` is present or a version token is absent; downloaded packages must *still pass the independent trusted CNMT scan*. Filename hints never authorize merging on their own.
- `verify_downloaded_patch` additionally rejects invalid/non-base IDs and non-newer requested versions **before opening the output package**, protecting against malformed restored batch jobs.
- `new_update_batch` excludes malformed/non-base library IDs and handles comma, newline and semicolon exclusion lists consistently with DLC matching.
- `stage24_catalog_filename_conflicts_fail_closed_before_queuing` and `stage24_cnmt_preverification_rejects_invalid_base_and_nonnewer_versions`: **PASS**, synthetic fixtures only; original games are never read or changed by these tests.

## Large catalog preview-cache accounting

- Changed `UpdateBatch` to track `preview_cache_bytes` incrementally instead of re-summing the complete `HashMap` on every new torrent preview. This eliminates a quadratic accounting loop when many different catalog items are scanned.
- The existing **128 MiB cache cap**, Arc-shared metadata payloads and one-preview-per-frame asynchronous audit behavior are preserved. Restored batches start with an empty cache and a zero-byte counter.
- The shared-preview regression asserts that a 3-byte synthetic torrent metadata payload occupies exactly **3 cached bytes**, while two missing DLC rows share the same preview allocation.
- No claim of a percentage speedup is made without a consistent real-world catalog-size benchmark.
